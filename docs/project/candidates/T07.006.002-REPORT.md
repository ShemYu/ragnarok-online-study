## API

`applyNavigationPortalPolicy(onlineText, workerText) -> {onlineText, workerText}` is pure: builtin `crypto` and `Buffer.byteLength` only, no file, network or process access. It refuses:

- non-string input, or size/SHA256 differing from the pins
- any anchor that is not a unique literal, or a host anchor outside the Navigation region
- overlapping hunks, or output above the frozen caps

All bytes outside the hunks are kept. Frozen `PINS`, `CAPS`, `NAVIGATION_REGION`, `HOST_HUNKS` and `WORKER_HUNKS` are exported for audit.

Caller contract: `Navigation.navigateTo({..., linkPolicy: "ordinary-portals-only"})` returns `true` when accepted. It returns `false`, before any change, for an unknown explicit policy or for tagged maps/coordinates that are not nonempty normalized strings or finite non-negative integers (no clamping, no invented 0/0). Without `linkPolicy` the manual path runs as before and returns `undefined`; raw `service`/`101` fields never opt in. `Navigation.getLinkPolicyStatus()` reports the generation, map and one of `none / inactive / idle / waiting / worker / routed / empty / unavailable`.

## Limitations
