## Frozen scanner policy and core

Expose `InventoryError` and
`scan_source(raw, *, max_bytes=8388608, max_occurrences=250000)`.
Require exact bytes input and exact nonboolean integer limits from0through
their defaults. Return exactly `{occurrences,known_prefix_end,gap}` without
changing inputs. Occurrences are:

```text
{literal_index:uint,span:[start,end],content_span:[start+1,end-1],content_hex:string}
```

Offsets are zero-based bytes, end exclusive. Preserve empty and repeated
occurrences. `literal_index` is contiguous from0per source. Hex is lowercase
and contains exact escaped spelling; no text decoding or unescaping.

Scan the entire file, including headers/data, under this deliberate policy:

1. Outside quotes, `//` consumes through LF or actual EOF. Bare CR does not
   end it. `/*` consumes through the first `*/`; block comments do not nest.
2. Byte0x22 opens/closes quotes. Inside quotes, comment markers are content.
3. Inside quotes, byte0x5c shields the following byte only when its immediately
   preceding **raw byte** is <=0x7e. Consume the pair once. Do not use Unicode,
   generic backslash parity or C/Python/JSON escape decoding.
4. LF, CR, NUL, BOM and high bytes are raw data. They are not native cutoffs.

This is **non-comment under this policy**, not under every native header rule.
An unquoted header `//` can suppress later quotes; quoted spans can cross native
newline/NUL rejection boundaries. Most unquoted names and dynamic display text
are outside this slice. Do not claim native script framing, compilation,
loading, event ownership, reachability, rendered text or translation quality.

On true EOF with an open quote (including eligible trailing backslash), stop
with gap `{reason:"unterminated_quote",span:[opening_offset,len(raw)]}`.
An unclosed block comment gives `unterminated_block_comment` from its opening.
Do not resume after guessing a later quote. Otherwise gap=null and
known_prefix_end=len(raw).

Scan only raw[:max_bytes]: both bytes of a comment opener must be inside
that prefix. A split opener gives a normal boundary after its first slash,
without out-of-budget lookahead. At a shorter budget boundary, give reason
`byte_limit`; gap starts at the opening of any unfinished quote/line-comment/
block-comment, otherwise the boundary. A quote/comment closed exactly at the
boundary belongs to the known prefix. Every gap ends at full len(raw), and
known_prefix_end equals gap.start. Keep only completed earlier occurrences.
Before opening another quote when max_occurrences has already been reached,
stop there with `occurrence_limit`. Comments/plain bytes still consume normally.
If byte and occurrence limits coincide, reaching the byte boundary wins.
Empty input with zero budgets is complete.
