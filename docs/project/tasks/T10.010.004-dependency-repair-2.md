## Required correction

- Derive the retained APK's own package name/version/architecture and full
  package-control identity from its bytes using a bounded metadata parser.
  Compare them with the claimed entry, installed DB identity, plan and full
  file hash. Do not merely check Q1 syntax, a filename or mutually agreeing
  export declarations. Apply the join to resolve and build qualification,
  including the complete offline input path. Make required raw bytes
  available to validation or bind the same already qualified input bytes.
- For the admitted APKv2 files, Q1 is Base64 of the SHA1 of the complete
  **compressed control gzip member**. It is not whole-file SHA1/SHA256 or
  .PKGINFO SHA1. Keep identity parsing separate from authentication: only
  real guest apk verify using stock keys establishes the latter. Never
  treat the signature member's filename or parser success as authentication.
- Bound compressed input, metadata decompression, member count and parsing.
  Read only signature/control metadata needed for the join; do not unpack
  package payloads, execute scripts or write parsed members into source.
  Refuse unsupported/truncated/ambiguous formats explicitly rather than
  guessing. No format support may be claimed beyond actual source/tests.
- Preserve authentication before install, all26 solver constraints, exact
  delta/base checks, real triggers, retained closure replay and existing
  Engine lifecycle. Do not relax source/ABI/crash requirements or substitute
  simulated success for future real APK qualification.
- Add meaningful controls for wrong C, wrong name/version/arch, corrupted or
  truncated control metadata and complete offline replay. Coherent checksums
  must not make contradictions pass. Synthetic fixtures may model trust, but
  must now contain the supported control structure and matching identities;
  do not add a production test-mode bypass for unsigned stand-ins.
