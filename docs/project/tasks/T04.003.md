# T04.003 — Taiwan item-table compatibility overlay

Owner: coordinator; code candidates: independent real Claude and Grok Orca workers. Parent T04 remains open. This brief is frozen in the implementation base commit recorded at dispatch. Both candidates start from that exact commit in separate Orca Git worktrees/branches. No shared app/database mutation by workers.

## Problem and intended behaviour

The supported Taiwan client loads an older compiled item table whose final values contain literal question-only resource names for 5449 items. Its supplied modern `iteminfo_new.lub` preserves the art names and Chinese text but fails roBrowser's whole-file UTF-8 detection because it is bytecode. [Verified diagnosis and input fingerprints](../reviews/2026-10-18-T04.002.md).

Build a local, reproducible converter that reconstructs the modern table as data and emits a **UTF-8 Lua source item table in a supported client-only mod**, using the existing loader's UTF-8 path. The resulting overlay should restore item art while preserving every final item ID, field, nested table and display string. Do not execute input bytecode, replace the whole game text with English, change protocol/langtype or game rules, rebuild the signed app, or rename/edit original assets. This source-overlay direction remains a hypothesis until root verifies actual loading and play.

## Candidate ownership and deliverables

Use Python standard library only. Own only new files under `tools/renewal/`: a converter CLI/module, focused tests and a short usage README. No tracked changes elsewhere, no network calls or new packages. Commit source/tests/docs on the assigned candidate branch; do not push or merge. Do not change `.gitignore`/publication policy. Generated tables, mod packages, reports with copied data and raw fixtures stay under that candidate worktree's ignored `.tools/` only.

Provide a CLI with explicit input path and output directory, input SHA-256 validation for the pinned modern table, safe no-overwrite behaviour, deterministic UTF-8 source output, `mod.json`, and a small metadata manifest (input hash, entry/field counts, output hash, converter version). Output layout must follow supported mod staging (`System/itemInfo.lua`); restrict applicability to twRO/Renewal where supported by the pinned manifest contract. Do not install or write to Application Support, original assets, any running app, another worktree, or coordinator evidence. No UI, game commands, SQL, credentials or process/network changes.

The parser is a deliberately bounded Lua 5.1 data-chunk reader: verify header/layout, bounded counts/offsets, complete consumption, supported top-level literal construction and duplicate assignments; reject unsupported execution/control flow, malformed/truncated input, invalid UTF-8, unexpected/cyclic values and invalid root item structures. Never execute a function/global call to parse the table. Serialization must preserve Lua types, scalar values, nested keys/lists, nil deletion and duplicate-key semantics, quotes, backslashes, control characters, multiline text and finite numbers. Avoid silent data loss and hand-written repairs of individual IDs.
