## 1. Generate

```sh
python3 -I -B tools/renewal/quest_true_text_mod.py --source FILE --output NEW_DIR
```

- `FILE`: the retained Traditional Chinese `OngoingQuestInfoList_True.lub`,
  2248204 bytes, SHA-256
  `49264cdd9b30ecad3416c721d153f91688455daa243e6af6ae04ad49bb805c00`.
  Any other length or hash, a missing path, a directory, FIFO or other special
  file, a symlink, or a symlink path component is refused (exit 2) before any
  output is created. Type and size are checked before the file is opened, and
  it is opened nonblocking without following links.
- `NEW_DIR`: must not exist; its parent must be an existing directory owned by
  the caller; no symlink component. Existing directory/file/symlink outputs are
  refused unchanged (exit 2).
- Slug is fixed `tc-true-quest-text`; there is no slug, pin or name override.

Success (exit 0) leaves exactly:

```text
NEW_DIR/                                                    0700
NEW_DIR/tc-true-quest-text/                                 0700  <- the mod
NEW_DIR/tc-true-quest-text/mod.json                         0600
NEW_DIR/tc-true-quest-text/System/                          0700
NEW_DIR/tc-true-quest-text/System/OngoingQuestInfoList-tc-true-quest-text.lub  0600
NEW_DIR/RESULT.json                                         0600  <- receipt, not part of the mod
```

`mod.json` is the profile's exact manifest (name, version 0.1.0, author,
description, `requires: {app: ">=1.6.3", era: "renewal"}`). The table is a
byte-for-byte copy; it is never decoded, transcoded, parsed or executed. Both
mod files are reread and compared with the bytes written before
`RESULT.json` (schema `ro-solo-true-quest-text-mod.v1`, status, slug, observed
input length/hash, two file records in order mod.json then table) is written
as `RESULT.json.partial`, reread and renamed into place. The same input gives
identical mod-file bytes on every run.

The corrected CLI is quiet on success: exit0 and the verified RESULT.json are
the completion evidence. It performs no stdout operation after publication,
so a closed output pipe cannot turn a completed copy into a reported failure.
Raw path components are checked before parent traversal; ordinary nonsymlink
relative paths still work. A post-mkdir chmod failure reports the retained
incomplete output, and a zero-progress write fails without looping.

On a write or readback failure the tool exits 1, prints
`incomplete output retained for review`, and leaves no `RESULT.json`. It
deletes nothing; the operator reviews and removes only that fresh output.

Before installing, Root rechecks the two mod files against `RESULT.json` and
the input pin. Copy only the inner `tc-true-quest-text/` folder; never copy
`RESULT.json` into the mods folder.

## 2. The supported route (why no Config or module patch)

- Enabled mods overlay after base/translation (`assets.rs:471`); their
  `System/` folder goes through `copy_system_layer` (`assets.rs:554–580`).
- A direct `System/OngoingQuestInfoList*.lub` or `.lua` file (case-insensitive,
  `client_tables.rs:475–477`) is kept aside in the merged System folder as
  `OngoingQuestInfoList-<safe>.lub` for the mod's first table, `.2.lub` and
  onward for later ones (`client_tables.rs:169–177`). With one file in one
  System root this mod yields `System/OngoingQuestInfoList-tc-true-quest-text.lub`;
  the input basename does not control the generated name, the mod folder does.
  Keeping one file/root avoids repeated-root generated-name reuse.
- The app inserts the generated `customQuestInfo` entry into the assembled
  client config it writes (`assets.rs:940–948`). **This tool writes no
  Config.local, `servers` object, plugin, client module or DBManager patch,
  and the operator must not hand-add a `customQuestInfo` entry.**

## 3. Ordering, naming and collision checks before install

- Client overlays follow **enabled folder scan order**: bundled `mods/` then
  user `state/mods/` collected into a name-ordered map (`mods.rs:1338–1358`),
  filtered by enabled state (`mods.rs:1477–1479`, used at `assets.rs:563`).
  Manifest `after` / applied ordering is a separate server-side sort; it does
  **not** order client overlays.
- The folder name is the mod's identity. A user mod with the same folder name
  **shadows** the bundled one (`mods.rs:1338–1355`).
- Mod names are sanitized for file names: anything but ASCII letters, digits,
  `-` and `_` becomes `-` (`client_tables.rs:441–447`), so distinct names can
  collide. The fixed ASCII slug is not proof of global uniqueness.
- Root must therefore list current bundled and user mod names, their roots,
  enabled state and the generated quest-table order, and confirm no other
  enabled mod sanitizes to `tc-true-quest-text`. Keep every unrelated overlay
  and Chinese setting enabled and in its existing order.

## 4. Load semantics to verify, not assume

- Quest tables load base alias first, then `SystemEN/OngoingQuests.lub`, then
  each `customQuestInfo` table **in array order**, even after an optional
  SystemEN failure (`DBManager.js:691–705`).
- A table registers each quest ID it names by **replacing that whole row**
  (`DBManager.js:5131–5143`); omitted IDs keep earlier rows. Full True
  intentionally replaces every ID it registers. Do not promise missing-only
  augmentation or field merging, and do not promise last-writer priority
  between quest mods; inspect the actual effective array.
- Config objects deep-merge but **arrays replace, not concatenate**, across
  base → local → optional extra config (`api.html:73–83`, `:99–102`). A
  generated duplicate key can displace a template's array.
- A selected-server key overrides the global key (`Configs.js:29–38`; globals
  snapshotted at init, `Configs.js:70–81`). Verify the **effective** list for
  the selected server contains this table and preserves the intended others;
  do not require a selected-server key to be absent.
- The decoder captures first-server `langtype` and `disableKorean` at module
  initialization (`DBManager.js:255–259`). Do not change Chinese settings for
  this overlay. Use the supported rebuild and a **fresh normal page**; never
  call `DB.lazyInit` again or clear caches by hand. Overlay fingerprints
  include enabled System layers (`assets.rs:646–704`).
