## Readouts and refusal semantics

getinventorylist exposes index, ID, amount, identify/refine/attribute,
cards, bound, expiry and equip fields. Iterate only below the current
@inventorylist_count: trailing array entries can survive a later call.
countitem excludes rentals and combines some metadata variants, so use rows
for structure. Temporary @ readout variables are not persistent test markers.

getinventorylist omits unique_id and uniqueitem_counter. Read them from the
isolated saved DB after normal logout. Weight refusal precedes UID generation;
full-bag refusal can follow it. A GUID counter advance on the latter can be
normal in both binaries. Compare the native baseline; do not demand every
failed insertion leaves every field unchanged. Multi-item nonstackable grants
can partially succeed, so deliberate refusal actions use amount1.
