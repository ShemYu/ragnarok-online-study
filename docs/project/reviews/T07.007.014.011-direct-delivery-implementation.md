`ROOT_ADMITTED=False`, `REQUIRED_HEAD=None`, `BINDING_PATH=None`,

- argv is non-empty; there is no CLI admission switch.

### Request loop (adapted GET34)

The loop runs one sequential connection per selected row, in global order:

1. `owners_check`.
2. Re-sample the row's loose and override targets. An existing target must be
   unchanged.
3. `HTTPConnection(host,port,timeout=remaining)` and `GET <exact wire>` with
   `Accept-Encoding: identity` and `Connection: close`.
4. `sock.settimeout(remaining)` before each read, where
   `remaining = min(deadline - now, 3 s)` and the deadline is 60 s from the
   batch start.

The response is refused when any of these holds:

- status is not 200;
- a `Location` header is present or the status is 3xx (`redirect`);
- `Content-Encoding` is anything other than absent or identity;
- `Content-Length` appears together with `Transfer-Encoding`, appears more
  than once with different values, or is not ASCII digits;
- `Transfer-Encoding` is anything other than `chunked`;
- the declared length is over 1 MiB (`declared_over_cap`) or differs from the
  metadata length (`declared_length_mismatch`).

Reads use `resp.read(min(64 KiB, 1 MiB + 1 - n))` until EOF, writing to an
exclusive 0600 `body-NNNN.bin`. The loop enforces `body_over_cap`, and
`aggregate_cap` at 32 MiB cumulative. The cumulative count starts from the
audited pilot's `pilot_response_bytes` for the remainder.

After EOF the loop checks, in order:

1. `short_body`
2. `size_mismatch`
3. `signature_mismatch`
4. `expected_sha_mismatch` (retained rows only)
5. A reopened stored body must match its bytes/SHA (`stored_body_mismatch`).

Errors are `deadline`, `io_timeout`, `incomplete_read`, `http_protocol`,
`transport`, `close_failed` and `write_failed`. The loop stops on the first
failed request. There is no retry and no replay.

### Settlement and postchecks

Settlement covers only the pending rows: attempted rows whose loose target was
absent before. Each poll uses a leaf `lstat`. A row is hashed only when its
file is present. A row leaves the pending set as soon as it stably matches its
complete response. Polling stops at `min(deadline, now + 2 s)` with 50 ms
sleeps.

Then one final complete pass samples every attempted row plus every
prior-present target (loose and override). It assigns these states:

- `unchanged`: the target existed before and is identical.
- `matched_new`: a new file matches the complete response.
- `shared_alias`: the same as `matched_new`, but the file shares dev/ino with
  its alias partner.
- `absent`: not fatal.
- `unverified`: present, but the request failed.
- `unsteady`: fatal.
- `mismatch`: fatal. This covers torn, wrong or mutated files, unsafe samples
  and override changes.

Unattempted and outside-batch rows are `not_observed`. Absent is never
reported as 404.

The postchecks cover:

- owners and the listener;
- native/INI/archive identities;
- environment and guard identities;
- every recorded parent (dev, ino, mode, uid, no symlink);
- re-hashing this source file;
- elapsed time against 60 s.

`first_error` is sticky. Later failures are appended to `postcheck_errors`,
and a postcheck-only failure also sets `first_error`.

### Output contract

The output is a fresh 0700 directory. Leaves are created with
`O_CREAT|O_EXCL|O_NOFOLLOW` and mode 0600:

- `BEFORE_ROOT.json`: all 1222 target states, parents, fixed identities,
  owners and the source pin.
- `response-NNNN.json`, `body-NNNN.bin`: four-digit global query index. Body
  files exist only after framing passes.
- `AFTER_ROOT.json`
- `RESULT_ROOT.json`

On success, exactly these files are present for the selected rows. On failure,
the explicit partial set is kept.

RESULT closed fields (types are asserted in source by `RESULT_TYPES` before
writing):

- `schema`, `task`, `batch`
- `profile_pin`, `binding_pin`, `pilot_audit_pin|null`, `source_pin`
- `materialization_required:false`
- `maps_unchanged`, `relations_unchanged`
- `query_ledger` (always 1222 rows)
- `counts`, derived from events
- `delivery_complete`, `materialization_complete`, `preservation_complete`, `batch_complete`
- `first_error|null`, `postcheck_errors[]`, `elapsed_seconds`
- `ambiguous_archive_queries:[1158]`, `archive_winner_claimed:false`

Each ledger row has exactly `query`, `wire_target`, `selected`,
`attempt_state` (`outside_batch|not_attempted|succeeded|failed`),
`expected_pin|null`, `metadata_bytes`, `observed|null`, `materialization`,
`alias_group|null` and `error|null`.

The response evidence records:

- `status`, `content_encoding`, `transfer_encoding`, `raw_declared_length`, `location`;
- `bytes`, `sha256`, `hash_scope` (`complete|prefix|none`), `http_eof`;
- the owned relative `body_file` and a 16-byte `prefix_hex`;
- `signature`, `classification` (`expected_match|new_observed|failed`) and `error`.

Stdout is one canonical JSON line of at most 4096 B. Handled stderr is empty.
Exit codes:

- 2: refusal, with no output directory.
- 1: an attempted run failed.
- 0: `batch_complete` only, which requires complete delivery and preservation
  with no errors. Materialization is not required.

## Limits

- **No runtime readiness.** `RealIO` (guard `exec`, `proc_pidpath`, `lsof`,
  real sockets) is untested by design: running it would need the guard and
  native processes. Root must qualify it with its own bound controls.
- The prefix is whatever `http.client` handed back from completed `read()`
  calls. When a socket error interrupts a buffered read, bytes already inside
  that read are lost (stdlib behavior, as in GET34). Bytes after a satisfied
  `Content-Length` are not observable through `http.client`.
- HEAD is checked only as equality between the slot and the binding. The
  source does not inspect git.
- Re-running a pilot binding is prevented only by Root's fresh output and
  binding discipline. The source cannot remember earlier runs. The remainder
  can never request pilot rows.
- Outside-batch absent targets are not re-sampled (`not_observed`). If the
  live client causes extraction elsewhere, that is not detected. Outside-batch
  existing targets are verified.
- Serial checks are observations, not an atomic race barrier. Settlement does
  not enumerate or retire outstanding server tasks.
- Cache provenance, the archive winner for 1158, decoding, rendering, travel,
  story, save and closure of the 82 gaps are not claimed. Signature and size
  checks are consistency checks only.
- Unknown billing and effective model remain unknown.
