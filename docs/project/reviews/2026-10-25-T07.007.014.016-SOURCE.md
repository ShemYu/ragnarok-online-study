### The five corrected areas

1. **Completion schema.** The gate now carries the canonical record fields
   `submissions/events/forward_count/late/duplicates`. Its helpers (`now`, `seq`,
   `onSettle`, `receivers`) are non-enumerable. After cleanup the runner stores
   `projectCompletion(gate)`, a checked, deep-frozen JSON projection.
   `evaluateControl` turns a record with a wrong or missing schema into a
   `completion_schema` FAIL instead of throwing. Evaluation runs only after
   cleanup and projection, and any evaluation exception is itself a FAIL record.
2. **Readback evidence.** `readTextureProbes` drains pre-probe errors first.
   It then reads each probe twice into a buffer prefilled with two different
   sentinels, and after every `readPixels` it runs a bounded (4) error drain
   that must come back empty and not exhausted. Any of these is an explicit
   failure: a throw, a GL error, an untouched buffer (zero or stale), a null
   FBO, an incomplete FBO, a probe outside the upload, or a throw from
   status/bind. The FBO is unbound and deleted in `finally`. `judgeUpload` now
   also requires `readback.readback_ok === true` and a clean, non-exhausted
   diagnostic drain. Consumer and diagnostic errors are still separate fields.
3. **Sticky failures.** `stickyFailures(rec)` covers driver exceptions, realm
   `error`/`unhandledrejection` records, any `forward_threw` event, a ground
   draw that threw and cleanup failures. Any of them adds a failing
   `no_sticky_failures` check, while every observed callback and upload fact is
   kept. A malformed control now also requires `native_load_events === 0`. The
   labelled injected GL fault is still an explicit expected control: it is a GL
   error, not a sticky failure.
4. **Ownership, deadlines and cleanup.**
   - `createRealm` registers the iframe in the runner's `owned` set before the
     first await. An owned `realmSetupMs` (3000) timer bounds iframe and script
     setup, and a missing accessor rejects.
   - `cleanupOwned` runs every release as its own step: own URLs, Worker
     revoke-ACK, Worker terminate, Worker script URL, textures, losing the
     context, restoring observers (`Texture.load`, the ground `drawImage`,
     `revokeObjectURL`, `Image`), timers and removing the realm. A step that
     throws is recorded in `cleanup.failures` (sticky) and the next step still
     runs.
   - A terminal is always published: `driver_exception` or `no_terminal` if
     the run is still pending.
   - `elapsed_ms` is always numeric. The per-control deadline check rejects a
     null elapsed time; before this fix, `null <= 2000` passed.
   - The runner (`makeRunner`) restores busy, buttons and status in `finally`,
     including when a run or render throws.
   - Run-all now records a `matrix` summary that FAILs over the 60 s budget or
     when any record FAILs.
5. **Ground 258/256 evidence.**
   - A new scaffold accessor, `groundContext: () => procCtx$2`, lets the runner
     install a context-local own-property `drawImage` observer before
     submission. It records the receiver identity, the source identity against
     the observed completion `this`, every argument and whether the call
     returned normally or threw. It forwards the actual `this` and arguments
     and returns or rethrows the native result. Only this observer is restored.
   - `judgeGroundDraws` requires exactly two normally returned 5-argument
     calls, `(canvas,0,0,258,258)` then `(canvas,1,1,256,256)`, on the owned
     receiver, from the first completion canvas. Both must come before the sole
     512×512 upload, using one shared sequence counter.
   - Valid ground controls need this check as well as the existing independent
     pixel and GPU probes. Null ground needs zero draws.

Only `--source`, `--metadata` (optional; used here) and `--out` are accepted.
Each argument may appear once and must be an absolute, normalized path.
The builder refuses the following before it creates anything:

- An existing output, even an empty directory, or a missing output parent.
- An output inside an input's directory.
- The wrong whole-source size/SHA or the wrong metadata size/SHA. Any metadata
  row must equal the builder table.
- A slice that is out of range or not at a line start, lacks a trailing LF, or
  has a different LF range, SHA or boundary text.
- A changed slice set, or the S09 assignment lines missing or out of order.
- The wrong driver size/SHA.
- A forbidden initializer in the assembled text: `init_Ground(`, `init_Water(`,
  `init$12(`, `init$13(`, `init_Map(`, `Ground_default`, `Water_default` or a
  column-0 `init();`.
- A network-capable token in a scaffold span.
- An input that changes between the PRE and POST descriptors.

Publication uses an exclusive `mkdir` (0700) and exclusive `wx` files (0600).
It then re-lists the directory and compares the bytes. If anything fails after
the directory is created, it removes only the paths this run created. The
builder starts no server, browser, Worker or network action.

Root serving the result: serve the generated directory (it must be a secure
context for `crypto.subtle`, so use `http://127.0.0.1:<new port>/`) and open
`index.html` in the Orca browser. The page fetches `MANIFEST.json` and
SHA-checks every listed file and fixture image pin. Controls stay disabled
until that passes (`#status[data-state]` ends as `ready` or `manifest_failed`).
There is one button per control/consumer plus **Run all controls**. Records
go to `#records`, a summary goes to `#summary`, and both are also available
as `window.__imageConsumerFixtureRecords`. A single control can also be run as
`await window.__imageConsumerFixtureRun(control, consumer)`. The page reads no
URL parameters.

## Driver design

The page creates a fresh iframe realm (`realm.html`) per control/consumer. It sets
`ROConfig.enableMipmap` and installs transparent realm observers, then loads
`production.js`. Only one control runs at a time, and buttons are disabled
while it runs. The observers are:

- An `Image` construct proxy that counts native Images and records their native
  load and error listener events. It does not set `onerror` on the consumer.
- A forwarding `URL.revokeObjectURL` that records sequence numbers, so the
  record shows a revoke before completion.
- `console.error`/`warn` forwarders and realm `error`/`unhandledrejection`
  records.

The record fields are:

- **Completion observer.** `Texture.load` is replaced with a wrapper that calls
  the unchanged original with the actual `this` and every argument. Only the
  callback slot is replaced. The observer callback records
  `canvas.width/height` (the completion canvas, never called natural or
  pre-allocation bounds) and the post-magenta pixels (≤1024 px). It forwards
  the actual `this` and arguments once while the gate is open. A closed gate
  records `late` without forwarding, a second call records `duplicate`, and a
  forwarded exception is recorded and rethrown. `procCanvas$3` is read
  separately as **pre-magenta**.
- **GL adapters.** An own-property forwarding adapter for `texImage2D` (and a
  `generateMipmap` counter) sits on the owned context returned by the
  unchanged `getContext`. It calls the native prototype function with the real
  receiver and arguments and returns its result. It records the actual upload
  source size and call count, then snapshots a tiny upload source after the
  forwarded call.
- **Independent checks after the terminal.** The driver drains up to 16 consumer
  GL errors, checks `isContextLost` and reads the texture: the ground atlas via
  `groundAtlasTexture()`, the water texture via the user callback. It then
  attaches an FBO, checks completeness and runs bounded 1×1 `readPixels` probes.
  Diagnostic errors are drained separately afterwards. Ground source probes read
  the actual `procCanvas$2`.
- **Upload verdict.** `judgeUpload` requires an observed call, no GL error, no
  exhausted drain, a live context, a texture object and a complete FBO. Decode,
  upload attempt, error, observed size/pixels and control expectation are
  separate fields. A callback or non-null texture is never sufficient.
- **Cleanup facts.** The driver revokes its own page and Worker-script URLs
  natively, asks the owned Worker to revoke its URL and then terminates it, and
  deletes textures. It loses the owned context with `WEBGL_lose_context`,
  clears every owned timer and removes the iframe.

## Limitations

- Every browser fact is still unobserved. These include whether Chrome decodes
  the hand-built JPEG and the BMPs, the exact canvas interpolation at the probe
  points, readback values, the timing of `WEBGL_lose_context`, Worker-created
  Blob URL resolution and its cross-realm revoke, and the run-all timing of
  ≤60 s. Root's Orca run is the first evidence for any of them.
- The probe tolerances (2–3 for BMP, 6 for JPEG) are authored judgements. A
  failure in a real run is a finding, not a reason to widen a tolerance.
- The function-scope wrapper differs from the original classic global scope.
  The production function bytes are unchanged.
- Memory, OS-hard-RSS, native or GPU containment is not claimed; the inputs are
  known tiny authored files only. There are no arbitrary or real image bounds,
  and no delivered image, header, body or archive was read.
- A page-created or owned-Worker Blob URL does not prove the installed
  production broker. Two consumers do not prove maps.
- This candidate closes no map, render, story, save or content gap. The full
  Renewal, functionality-first, Traditional Chinese and party-later scope stays.
