## API and behaviour

`TransportCapture()`, `record(kind, connection=None, **primitive_fields) -> bool`, `finish() -> dict`. The module uses Python 3.9 stdlib only and imports only `copy`, `json` and `time`. It has no CLI, no I/O, and no socket, process, thread or callback code. It defines no hooks or wrappers. The only import-time computation is the constant `ENVELOPE_RESERVE`.

- **Event kinds.** The module implements exactly the eight contract kinds and their exact field sets. Missing or extra fields are rejected with `fields_mismatch`. Strings must be exact `str` and fit their UTF-8 bounds. A string that cannot be encoded as UTF-8, such as a lone surrogate, is rejected. Integers must be exact `int`, so bool is rejected. `errno` must be `None` or an int in the signed 64-bit range. That range bound is my addition; the contract says only "exact int". `row_index` must be 0..1023 and `confirmed` must be an exact bool. Float, NaN, Inf, bytes, list and other non-primitive values are rejected. Values are never coerced, and caller objects are never mutated.
- **Identity.** A connection must not be `None` or an instance of a primitive type. That check uses `issubclass(type(connection), ...)`, which never touches the instance. Active objects live in a dict keyed by `id(connection)` and are confirmed with `is`. The module holds a reference only while the connection is active. The active `id()` therefore cannot be recycled, and a fresh accept always gets the next never-reused `connection_id`. The module never reads attributes, hashes, compares for equality, calls `repr`/`str`/`bool`, or calls fileno/close on the object. A descriptor number such as `7` is rejected as `connection_primitive`.
- **Order rules.**
  - `listener_ready` is accepted at most once.
  - `accept` must not repeat an already-active object.
  - `accept_error` must use `connection=None` and allocates no id.
  - `request` needs an active connection and is accepted at most once per connection.
  - Associated `native` needs a prior GET, at most one native event per connection, and a wire other than `/api/health` or `/api/cache-stats`. Native events with `connection=None` are retained with `connection_id: None`.
  - `row_index` is unique globally.
  - `handler_error` and `log_error` accept `None` or an active connection. They need no path, command or request_version.
  - `close` releases the reference. A closed object later counts as unknown.
  - A listener_ready-before-accept order is **not** imposed, because the contract does not state it.
- **Faults.**
  - Each rejection returns False and latches the first `{code, attempt}`, with a fixed code of at most 64 ASCII bytes.
  - A rejection changes no connection, request or native state; `attempted` and `rejected` still advance.
  - Later valid observations are still retained, but the result can never become complete again.
  - An unexpected internal exception becomes `observer_internal_error` instead of raising into the caller.
- **Caps.** Rows are capped at 8192. The entire result is capped at 1048576 bytes under the exact compact `ensure_ascii`/`allow_nan=False` measurement. Before committing a row, the module checks the worst-case envelope reserve plus the row text and commas against the cap. The worst-case reserve assumes every counter and fault attempt is 10^19 and the fault code is 64 bytes. A prospective row that does not fit is never committed, and the first fault becomes `row_cap` or `byte_cap`. After a cap, every later call returns False with `capacity_exhausted` accounting and changes no state. Rows are never truncated.
- **Complete.** A result is complete only when there is no fault, `listener_ready` was retained exactly once, no connection is active, and no close was recorded with `confirmed=False`.
- **Finish.**
  - The first call snapshots the counts first, then releases every active reference without any physical cleanup.
  - It then seals and stores a private deep copy.
  - Every call returns a fresh deep copy.
  - A `record` call after sealing returns False and changes nothing, including `attempted`.
- **Timing.** `elapsed_ns` is genuine `time.monotonic_ns()` minus the value at construction and is never supplied by the caller. `sequence` is the pre-seal attempt ordinal, so rejected attempts leave gaps.
- **Threads.** The class is unsynchronized by design: the brief allows no thread implementation. ROOT must call it from the serial serve thread, or from the main thread only while the proxy is stopped, which matches the lease's ownership.

## Limitations and claim boundary

- This is source-only, in-memory evidence accounting. Integration is pending and owned by ROOT. No runtime, client, browser, native, upstream-body, local-send, worker-receipt or physical-close result follows. Readiness, rendering, cause and full-game acceptance also do not follow.
- A record with `confirmed=True` is the caller's statement. It does not prove that a physical close happened.
- The overhead and timing perturbation of `record`/`finish` in the real serial server were not measured. Each row calls `json.dumps` once. The active table is O(1) per call.
- The 64-bit `errno` bound and the absence of a listener_ready ordering rule are interpretation choices for ROOT to keep or change.
- ROOT still owns:
  - the actual hook return/identical-throw/callback/cleanup semantics;
  - forwarding observer rejection to the existing failure callback;
  - the real close audit and the join between native rows and actual upstream rows;
  - the one fresh fruit probe.
- Not done: no acquired source was executed or imported, and no socket, server, network, SQL, save or settings action was taken. Nothing was installed globally, no subagents were used, no sibling or worker output was read, nothing was pushed, and nothing was merged.
