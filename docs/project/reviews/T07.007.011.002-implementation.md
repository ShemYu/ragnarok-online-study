## Change

In each bundle, the tool changes only the class method
`calcNormal_SMOOTH(normal, groupUsed, group)`, with one pure insertion directly
before the original line `len = 1 / Math.sqrt(x * x + y * y + z * z);`:

```js
if (x === 0 && y === 0 && z === 0) {
	norm[l] = 0;
	norm[l + 1] = 0;
	norm[l + 2] = 0;
	continue;
}
```

These lines use the same indentation as the original `len` line. `continue`
still runs the original loop increment `++v, l += 3`. A non-zero sum reaches the
original reciprocal and the three original multiplies, whose bytes are
unchanged; the tool deletes no bytes. No `isFinite` scrub, epsilon, alternate
norm or geometry change is added. In `Online.js` the free, already-guarded
`function calcNormal_SMOOTH(node, …)` (RsmEffect helper) is located after the
hunk and is byte-identical.

API: `patch_bundle(data: bytes, bundle: str) -> bytes`, where `bundle` must be
`worker` or `online`. A wrong argument type raises `TypeError`, including
bytearray, memoryview and str. Unknown selector, wrong length/hash, truncation
or changed bytes raise `PatchError`. Input that is already patched (pinned output
hash or guard present) raises `AlreadyPatchedError`. The function also asserts the
pinned header, insertion and method-end offsets, the original and patched method
SHA256 and the full output bytes/SHA256.

CLI: `python3 -I tools/renewal/zero_sum_normal_repair.py --input-root PATH --output-dir PATH`.
- **Refusals:** an existing (or dangling-symlink) output destination, an input
  root that is not a directory, and symlinked, hard-linked or nonregular inputs.
  Inputs are read with `O_NOFOLLOW`, and their identity is checked across lstat,
  fstat and after reading.
- **Order:** both inputs are validated and patched in memory before anything is
  written. The tool then creates the output directory exclusively (0700) and
  writes the two bundles with `O_EXCL` (0600). It re-reads the sources (identity
  and hash unchanged) and the outputs, and writes `manifest.json` (0600) last.
- **Failure:** exit code 1 and no success manifest. Partial owned outputs are
  not deleted.
- **Manifest:** a deterministic body (patch id/version, per-file input and output
  bytes/SHA256, one hunk record with the inserted text) plus a separate
  `runtime_receipts` key (UTC time, source hash before/after, identity flag,
  output readback hash). It contains no absolute paths.

## Limitations

- **Expected-zero slots:** these are hand-declared per fixture, not computed by
  a second implementation.
- **NaN payloads:** NaN words are compared by class, not payload.
- **Not executed:** no bundle import, constructor, shader, browser, native
  reader, app, SQL, save, network or host-setting action.
- **Not checked (root's later gate):** real-data packet reconstruction (the
  expected 108 changed words / 216 differing bytes), the repaired-pair observer,
  the four-map material/placement/partition/decoder/GPU/frame checks and the
  remaining animation.
- **Directory modes:** the test helper's `os.makedirs` created the parent
  directories `.tools` and `.tools/renewal` with umask 0755 on first run. I set
  them to 0700 by hand afterwards; the helper only enforces 0700 on the
  candidate directory and its children.
- **Hard links:** these are refused for inputs (nlink ≠ 1). An admitted frozen
  root that uses hard links would need an explicit contract change.
