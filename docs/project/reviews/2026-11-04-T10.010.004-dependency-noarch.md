## Change

Allowed paths only: `build_recipe.py`, `build/guest_lib.sh`,
`test_build_recipe.py`, `BUILD_RUNBOOK.md` and this report.
`build/guest_build.sh` did not need a change: `apk --print-arch`, `EXPECT_ARCH`
and the `ld-musl-$EXPECT_ARCH` check stay strictly `aarch64`.

- **Native target.** New `NATIVE_ARCH = "aarch64"` feeds `EXPECT_ARCH`,
  `abi_expect.arch` and the default `load_local_manifest(arch=)`.
  `dependency_arches(native)` returns `(native, "noarch")` and refuses any
  native value other than `aarch64`. The ELF/interpreter checks are unchanged.
- **Plan / local loader.** The five-field manifest API is unchanged. The arch
  is derived from the file's own control member and must be exactly `aarch64`
  or `noarch`. The actual value stays in `identity.arch` and in the plan's
  `apk_local[].arch`. The internal `apk-local.list` gains a seventh field,
  `<arch>`, bound by `LOCAL_LIST_SHA256` as before.
- **Guest.** `dependency_arch()` accepts `$EXPECT_ARCH` or `noarch`. It refuses
  when `EXPECT_ARCH` is empty or `noarch`. `check_local_list` refuses a missing
  or foreign planned arch. `verify_apk` still requires a size/SHA recheck and
  a real `apk --no-network verify` OK with the stock keys. It then requires a
  dependency arch, equal to the planned arch for local inputs, and writes the
  **actual** arch into `apk-verify.txt`. No `--arch`, key import, trust or
  script bypass, fallback URL or recursive fetch was added.
- **Host export join.** A verification row's arch must be a dependency arch.
  The verified arch is kept per closure entry and must equal the raw control
  arch of the same bytes. For a planned local input, the plan's `arch` must
  also equal it; a missing or contradictory plan arch refuses. The resolve
  `MANIFEST.json` view now compares arch too. Closure, `derived_identity` and
  `dependency_closure` carry the actual arch.
- All N/V, full-SHA, size, Q1, installed `C:`, inventory, base, delta, offline,
  signature, WANT/libunwind, lifecycle and fd0 checks are untouched.

## Tests

The 86 existing cases are retained. Fixture changes only:

- `dep_evidence` writes the bytes' actual arch into verification rows.
- `write_local`/`relist` emit the seventh list field.
- One list-line assertion includes it.

Five new cases are in `NoarchDependencyTests`:

1. **Local planning.** In both modes, noarch is kept for `git-init-template`
   and aarch64 for the three development files. The plan, upload list and env
   keep `EXPECT_ARCH='aarch64'`. Refused before a run directory exists:
   `x86_64`, `riscv64`, empty, `Noarch`, `noarch␠`, `aarch64,noarch`, `all`,
   and native `noarch`/`x86_64`/empty.
2. **Guest (modelled apk).** Noarch local and noarch repository additions are
   verified, with actual rows. The retained MANIFEST keeps noarch. Refused
   before the solver: noarch bytes planned as aarch64; aarch64 bytes planned
   as noarch; planned arch missing, unknown or a quoted-empty token; an
   unsigned noarch input; x86_64 bytes with a coherent list hash. Also refused
   before install: an x86_64 repository addition, and `EXPECT_ARCH=noarch`.
3. **Resolve export join.** Same refusals as the build join below, run on a
   resolve export (hashes, `C:` and Q1 stay coherent; one arch record differs):
   - verification row: local noarch row → aarch64; native row → noarch; repo
     noarch row → aarch64; unknown, x86_64 or missing row arch;
   - noarch repository bytes swapped for aarch64 bytes with hash and `C:`
     rebound;
   - x86_64 bytes with or without the row rebound;
   - plan arch missing, noarch→aarch64, aarch64→noarch or unknown (each on a
     copied run directory).
4. **Build export join.** The same counterexamples on a build plan. Local
   bytes come from `upload.tar`.
5. **Private actual input.** Requires both `T10_APK_IDENTITY_DIR` and
   `T10_APK_SIMULATE_LOG`; public runs skip it.
   - Reads the five frozen APKs once and checks four aarch64 SHA/arch values.
   - Checks the actual noarch N/V, arch, Q1, SHA-256 and size.
   - Builds an isolated-copy manifest of the actual noarch and three
     development files.
   - Parses the actual 47-row log with the real guest parser; it includes
     `git-init-template=2.52.0-r0`.
   - Plans resolve from those bytes; the plan keeps `noarch`.
   - Replays the modelled guest transaction from the plan upload, using the
     actual log as solver output. The row is `noarch`; the other 46 are
     `aarch64`.
   - The guest refuses the actual noarch file when it is planned as aarch64.
   - The host export validates. An aarch64 verification row and an aarch64
     plan arch are each refused.
   - Reconfirms the packet bytes were unchanged.

## Limitations

  `apk verify`, a noarch install, scripts/triggers, a closure or a build.

  upload/list SHA-256 pins from earlier plans no longer apply. Root must
  rebind source pins before a host helper or all-local wrapper uses this code.
- The all-local/compiler wrapper drafts and the private host helper are
  outside this scope and were not changed.
