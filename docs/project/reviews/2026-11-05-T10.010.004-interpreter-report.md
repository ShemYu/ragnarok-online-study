## Fix

The old guest statement was:

```sh
readelf -l "$OUT/$v/map-server" | grep -A1 INTERP > "$OUT/$v/interp.txt" || true
```

GNU `readelf -l` wraps each 64-bit program header over two lines. The old
`grep -A1 INTERP` therefore kept the offset row and the size row. It dropped
the next line, `[Requesting program interpreter: ...]`. The `|| true` also hid
any `readelf` failure. The new statement is:

```sh
readelf -l "$OUT/$v/map-server" > "$OUT/$v/interp.txt" || die "$v readelf -l"
```

The new statement saves the complete, unfiltered program-header report. It has
no pipeline, so the exit status is the status of `readelf` itself.
`die` (in guest_lib.sh) writes `FAIL <v> readelf -l` to RESULT and exits 1. The
file name `interp.txt` stays the same.

These parts are unchanged: the host validator (`build_recipe.py`, the substring
check for `/lib/ld-musl-aarch64.so.1` in `interp.txt`), the recipe, the
controller, resources, ABI, sources, toolchain, flags, the patch and every other
guest line. The full program-header text can contain the musl path only on the
interpreter-request line. Section names such as `.interp` do not match it. The
strict check is therefore no weaker.
