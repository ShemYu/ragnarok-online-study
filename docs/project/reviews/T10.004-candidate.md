## Choices for Root review

1. Callback functions are required before input validation. A missing callback is `callback` even when the input is also unusable. Callback throws, non-string decode results, and non-lowercase-64-hex hashes are `callback`.
2. Limits use binary KiB/MiB. Compact input size matches `JSON.stringify` UTF-8 and stops past 1 MiB, including a shared DAG, without an unbounded expansion. Codes: `input`, `limit`, `callback`, `unicode`, `mutation`.
3. The row table is typed depth 1. Depth 33 is `limit: depth`. JSON container nesting above 2048 is `limit: nesting` so a tower cannot overflow the stack. Typed depth 32 fits under that guard.
4. Match and table order is strict `JSON.stringify` of `T(key)`. Duplicates and inversions are `input: order`. Negative-zero keys (`0000000000000080`) refuse; negative-zero values remain. Hits are copied in input order and are not re-searched or reordered.
5. Fields are Title, Summary, Description, its immediate members in their existing canonical order, IconName, NpcSpr, NpcNavi. Byte-valued Description members use `decode(bytes,'big5')` even if the member key spells IconName. IconName, NpcSpr, and NpcNavi use `decode(bytes,null)` and are labeled `windows-1252`. A byte-valued Description parent is `nonbytes` and is not decoded. Deeper descendants are not decoded.
6. The prefix is a separate decode of the bytes strictly before the first `0x00`, including an empty prefix. Full decoder text stays, including NUL, newline, and literal NAVI/color markup. U+FFFD indexes are Unicode scalar indexes.
7. Result growth is counted inside the trailing `rows` and `fields` arrays before each push, then the finished document is checked again. Copied key/record/clue/hit values keep input key order. Objects this module builds use the key order named in the task.
8. Fresh callback arrays are compared when the callback returns. A mutation that is restored before return is not detected.
