### Corrections

1. **Observation order: preservation/close before reduction.** In the job
   loop, postcheck failure and the body-close outcome now apply to the verdict
   immediately after the Worker's `finally`, before `reduceModel` runs.
   Reduction runs only when the verdict is still `returned`. A known postcheck
   or close failure therefore skips the reducer. The reason
   `reducer skipped after body preservation/close failure` is added only when
   the Worker verdict had returned. An earlier constructor/summary/lifecycle
   failure stays primary. Postcheck stays ahead of close, matching the order
   they happen. A close after another primary failure is still appended as a
   later `body-close`. The bounded result file is still retained, and
   `reduced` is null. Later jobs stay `not_started`. The existing
   `closeIsPrimary`, fail-stop and retention code is unchanged apart from its
   position.
2. **Literal FD accounting includes partial opens.**
   - When a read fails after `openSync` succeeded, `readPinnedFile`'s existing
     catch makes its single close attempt as before. It then attaches
     `fd_opened:true` and `fd_close_error` to the thrown object. The message
     still keeps the primary error with the close failure appended.
   - A small exported helper, `partialOpenOf(e)`, reads those fields. It
     returns `null` when the thrown value is not an object and so cannot carry
     them.
   - Body staging and final-reread catches call `recordPartialOpen`. This
     counts the literal open, and a failed close stays counted open. Each close
     failure counts once.
   - The postcheck reread catch now sets `reread_opened`/`reread_fd_closed`
     for an opened-then-failed reread.
   - When the outcome cannot be known, the manifest publishes
     `max_open_body_fds:null`, `close_failures:null` and
     `literal_accounting:'unknown: …'`, never a definitive count.
   - There is no retry, no inference of closure from an exception, no new
     framework and no change to logical staging (`max_staged_bodies`).

Unchanged: authority split, full-profile/complement admission, public null
binding, full-summary retention and string accounting, relation joins, all
caps, suffix, parser and default refusal.

### Corrections made

1. **Truthful close outcomes.**
   - `closeFd` makes one close attempt and returns the error. It never
     retries an ambiguous descriptor.
   - Body close after the Worker: a close error records
     `fd_closed:false` and `close_error`, and fails the job.
     - If the job had otherwise returned, the close failure is the job's
       primary failure (`host`).
     - If the job had already failed, that failure stays first and a
       `body-close` failure is appended to `later_failures`.
     - In both cases the run stops further jobs and cannot publish
       `observed`.
   - Held profile/admission/unbound/pilot/prefix/summary/suffix descriptors
     are closed inside `execute`. This happens after postchecks and final
     rereads and **before** the status is computed and `MANIFEST.json` is
     written. `held_closes` is published, and any failure is a `held-close`
     failure. `runHost` closes only descriptors not yet attempted. On an
     exception path the primary error message is kept and close failures
     are appended to it.
   - `readPinnedFile` exception path: the read error stays primary and a
     failed close is appended to its message, so it is no longer replaced
     by the close error.
   - The postcheck reread close, final-reread close, `describeFile` close and
     Node close are all checked.
   - FD accounting is split:
     - `body_fds.max_staged_bodies`: logical bodies, 1.
     - `body_fds.max_open_body_fds`: literal, counted at the host's own
       open/close sites, including the postcheck's second descriptor. The
       expected value is 2.
     - `body_fds.close_failures`.
2. **Constructor-return fact.** The suffix sets `constructor_returned=true`
   immediately after `new RSM` returns, before the deadline check. The catch
   keeps an existing `true`, so a post-return timeout or summary error
   reports `true`. A constructor throw stays `false`.
3. **Authority split.** The inert `ROOT_BINDINGS` and `RUNTIME_PROFILE_PIN`
   slots are removed. One `ROOT_SOURCE_BINDING` remains, `null` in public
   source.
   - `validateBinding` runs before any read. It requires exactly
     `{execution_admitted:true, runtime_profile:{bytes,sha256},
     admission_projection}`. The projection keys are exactly the admission
     keys minus `host`, and the projection's `profile_sha256` must equal the
     profile pin.
   - `checkAdmissionProjection` runs right after the admission is parsed and
     before the unbound/profile joins, output creation, body staging,
     evaluation or any Worker. The admission minus `host` must be
     `isDeepStrictEqual` to the bound projection. That projection covers
     mode, full profile hash, required HEAD, fresh output path, exact
     selected indices, exact consumed-pilot manifest/audit descriptors and
     indices, and the approved guard qualification.
   - `host` is the only excluded field. It is still checked against the
     running source's descriptor. The complete admission is not pinned
     inside the host, which avoids a circular self-hash.

     no CLI self-admission.
   - Node, suffix and bodies are bound transitively by the pinned profile and

   - `runtime_ready` exists only as `claims.runtime_ready:false`. It is not

### Suffix (`direct_model_probe_suffix.js`, 4348B, `6e0350f0…`)

This file derives from the T07.007.014.004 suffix (`27d77dbd…`). It keeps the
same 48s inner deadline, `crypto.subtle` SHA-256 and 8MiB no-truncation
result rule. The RSW/GAT/GND fetch body is replaced as follows:

1. Take one host-handed exact standalone `ArrayBuffer` and check its bytes and
   SHA-256.
2. `new RSM(buffer)`. A throw gives `constructor_exception` with the error
   retained; `constructor_returned` is false.
3. `ROOT_MODEL_SUMMARIZE(model)`. The result is `summary_error` or
   `summary_limit` (by the `SummaryLimitError` name). Deadline expiry gives
   `timeout`.
4. Post-check the input buffer hash.
5. Encode the result. If it exceeds 8MiB, the outcome becomes `result_limit`
   with no partial summary.

The suffix posts one `ROOT_MODEL_RESULT`. It is used unchanged, with no
per-job projection. Root binds it through the runtime profile's
`model_suffix` descriptor. `checkSuffix` refuses a suffix whose deadline,
8MiB bound or protocol tokens differ, or which contains `fetch(`,
`.compile(`, `.compileAtFrame(`, `.createInstance(`, `MapLoader.` or
`FileManager.`.

### Worker scope bridge

- Each selected model gets one fresh sequential `Worker`. It verifies the
  prefix, suffix, summary and body against their pins, then runs
  `import()` on the exact staged summary bytes as a base64 `data:` module,
  unmodified.
- `summarizeModel` is installed in a frozen, non-writable, non-configurable
  global `ROOT_MODEL_HOST = { job, summarizeModel, takeBody }`. Only then is
  the classic prefix+suffix evaluated with `vm.runInThisContext`.
- Supplied globals: `self`, `postMessage`, `fetch` (always rejects and logs
  the attempt), `performance`, `crypto`, `TextEncoder` and `TextDecoder`.
- `takeBody` hands out one standalone copy. A second call throws and is
  counted. `CLOSING` reports:
  - the fetch attempts;
  - the handout count;
  - the handed-buffer post-hash;
  - the handler settle or rejection;
  - post-terminal messages.

### Domain preservation

- `validateUnboundDomain` checks all typed joins on the pinned unbound
  profile. A global query index never stands in for a model index, and the
  validator refuses a relation joined by model index.
- The 3 case groups and 6 rows stay unverified, unmerged and unhashed. Their
  wire targets stay case-distinct. `physical_input_alias_group` must equal
  the group membership.
- `validateProfile` reads the unbound profile through its pin (2538357B,
  `c7d4f10d…`). It requires `model_group_relations`, `maps` and
  `case_alias_groups` to be deep-equal to the unbound profile. Each model
  record must be deep-equal apart from one added `body` (a descriptor or
  `null`). Nulls, indices, pointers, holds and case distinctions therefore
  survive unchanged.
- A shared body path is refused, because actual case/path sharing is
  Root-bound. Identical hashes at distinct paths stay separate logical jobs.
- A known retained pin must equal the bound body.
- The full typed `source_record` is copied into each model report.
- Placements are never fabricated. Source links carry only
  `core_group_pointer` and relation/map indices.

### Results, failures and the reducer

- Every model in the profile gets a manifest `jobs` row with one of these
  statuses: `outside_batch`, `not_started` (with a reason), `returned` or
  `failed`.
- A failure has one of these classes: `constructor`, `summary`, `reducer`,
  `limit`, `preservation` or `host` (bootstrap/lifecycle/staging/execute).
- Any failed job stops the run. No job is retried.
- `first_failure` is sticky. Later failures are appended to `later_failures`,
  including source post-check and final body-reread preservation errors.
- Retained files:
  - `model-NNNN.result.json`: the exact encoded string from the worker, which
    contains the complete unchanged `summarizeModel` output;
  - `model-NNNN.host.json`: lifecycle, closing, source record, body
    post-check, exception and reducer output;
  - `NESTED_TARGETS.json`;
  - `MANIFEST.json`;
  - `RUN_DEADLINE.json`, written only when publication is late.
- `reduceModel` recomputes the fixed stage rule independently:
  1. prefix once;
  2. ECMAScript `trim` of the whole name;
  3. backslash to slash;
  4. `encodeURIComponent` per segment.

  It also checks the exact declaration keys, every slot reference and
  resolved/unresolved state. It keeps unlinked declarations and zero-face
  links, and lists unresolved slots explicitly.
- `nestedTargets` groups exact `http_path` strings, case-sensitive and never
  lowercased or decoded. Each group lists every declaration and the source
  links (relation, map, core group pointer).
- If any selected job did not return, `targets` and `totals` are `null` and
  `unknown_model_indices` is listed. Unknown results are never published as an
  empty table.

### Bodies and file descriptors

- One body is staged per job with `readPinnedFile`. After its Worker settles,
  it is post-checked and its file descriptor is closed.
- `max_concurrent_body_fds` is recorded.
- After all jobs, every selected body is reread fresh, one at a time.
- Held throughout: profile, unbound profile, admission, pilot manifest/audit,
  prefix, summary and suffix.

### Authority

- `RUNTIME_PROFILE_PIN = null`. `ROOT_BINDINGS` has every slot null or false.
  The CLI refuses with exit 2 before any file read, output creation or Worker
  start, and `runHost` without the test-only `testing` argument does the same.
- The admission takes exactly these 11 keys and has no self-admission field:
  `schema`, `root_bound`, `execution_admitted`, `mode`, `profile_sha256`,
  `host`, `output_path`, `required_head`, `outer_guard`,
  `selected_model_indices` and `consumed_pilot`.
- `mode` is `pilot` or `remainder`. A remainder needs:
  - an observed pilot manifest of the same profile in which every pilot job
    returned;
  - an independent Root `PASS` audit that binds that manifest's SHA-256 and
    indices;
  - a strictly disjoint selection.
- The host only records `required_head` and `outer_guard`. It runs no Git and
  provides no containment.

### Synthetic controls

These use only authored bytes: a tiny classic prefix with an authored `RSM`
(`GRSM`+JSON), an authored summary stand-in using the same declaration rule,
and authored bodies. The synthetic domain is full size: 936 models, 1649
relations, 21 maps and 3 case groups/6 rows. Global query index = 2·model+5.

1. **Default refusal:** no-I/O CLI exit 2 and `runHost` refusal (`unbound`);
   the directory stays empty and every Root slot stays null/false.
2. **Typed joins:** 15 tampering refusals, including:
   - query joined by model index;
   - merged or hashed case group;
   - lowercased wire target;
   - changed or extra record field;
   - missing body slot;
   - shared body path;
   - retained-pin mismatch;
   - 935 models;
   - map index mismatch;
   - case-row join;
   - body over 1MiB;
   - limit change;
   - admitted unbound flag.
3. **Literal path stages:** `' Foo\Bar Baz.bmp '` →
   `data/texture/%20Foo/Bar%20Baz.bmp` (trailing whitespace trimmed, inner
   leading space kept). Latin-1 `Ç®a.bmp` → `%C3%87%C2%AEa.bmp`; `A.BMP`
   stays uppercase; trim covers NBSP and U+3000. Suffix bound/deadline/fetch
   refusals.
4. **Pilot [3,5,10,20]** with literal expected values:
   - unchanged summary textures and slot states;
   - unresolved slots `-1/99/1.5`;
   - an unlinked declaration and a zero-face link;
   - 7 exact case-distinct nested targets, with `shared.bmp` grouped across
     models 3 and 5;
   - totals 5 nodes, 9 declarations, 11 slots;
   - case rows 10/20 have the same SHA at distinct paths and run as two
     returned jobs;
   - `max_concurrent_body_fds` = 1 and the process FD count is unchanged;
   - modes are 0700/0600;
   - positive exit, both streams drained, one handout, no fetch.
5. **Constructor throw:** the exception is retained, `constructor_returned`
   is false, and the later job is `not_started`. The first failure is sticky
   and the nested table is `null`/unknown.
6. **Distinct failure classes:**

   | Case | Class / outcome |
   |---|---|
   | Summary error | `summary` / `summary_error` |
   | Summary limit | `summary` / `summary_limit` |
   | Declaration skew | `reducer` |
   | 9MiB result | `limit` / `result_limit` |
   | Constructor mutating its input buffer | `preservation` |

7. **Reducer-global cap:** a declarations overflow is a `limit` failure with
   partial evidence (`returned_model_indices` [3], targets null). The JSON
   depth cap is also checked.
8. **Lifecycle:** each case is classified as a `host` failure with a specific
   reason:
   - missing THREAD_READY;
   - double THREAD_READY;
   - early result;
   - duplicate result;
   - missing result, ending at the 1.5s worker deadline with the owned worker
     terminated;
   - asynchronous uncaught error;
   - stdout over the cap;
   - an attempted fetch.

   A changed suffix protocol is refused before any Worker starts.
9. **Body changed after admission:** a staging refusal is the sticky first
   failure, and a later preservation failure is recorded at the final reread.
10. **Publication:** a reused output directory is refused (EEXIST) before any
    Worker starts. The retained-bytes cap gives a `limit` failure.
11. **Admission:** 13 refusals, none of which creates an output directory.
    Then pilot → Root audit → disjoint remainder [5,10,20] is observed, and
    the pilot row is `outside_batch`.

## Limitations and unexercised real-runtime functions

These are open for Root:

- Never evaluated:
  - the real 624463B prefix;
  - its real `RSM` and `BinaryReader`/codepage behaviour;
  - the real `summarizeModel` (`ec51b8b2…`) on a real constructed model,
    including its `explicit()` projections, numeric statistics and
    `SummaryLimitError` budgets;

  It is unknown whether real models construct, throw, fit 8MiB per model or
  185597952B in total, fit 48s/55s/1240s, or fit 1024MiB heap / 1610612736B
  sampled RSS.
- The `data:` summary import has been exercised only with an authored module.
  JSON encoding drops `undefined`-valued summary keys exactly as
  `JSON.stringify` does. The summary itself makes the specials explicit.
- Real `onmessage`/THREAD_READY ordering in the prefix is inherited from
  .009's qualified handshake, but has not been re-observed with this suffix.
- The host performs no RSS sampling or containment. Root's outer guard is
  required.
- The host records `required_head` but does not verify it.
- Node identity has been checked only against the test machine's binary.
- Root must still supply:
  - actual body descriptors for 843 models;
  - `.011` delivery evidence;
  - case/path/hash alias decisions;
  - the runtime profile and its source pin binding;
  - the pilot selection and audit;
  - a fresh output path.
- Construction does not prove anything about compile, instances, image decode,
