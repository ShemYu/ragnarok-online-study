## Design

**Common** (`prontera,150,150`, `T10 Ordinary Items#t10oi`): GM-level gate,
one `select` of read-only or one of ten fixed commands (909 x2/x3/x1,
BOUND_CHAR 909 x1, rental 909 3600s, Knife x2/x1, getitem2 +4 Fabre Knife,
12900 x2/x1), then cancel. Each choice logs `before`, `action` (command text
and epoch) and `after` snapshots. Each snapshot logs actor char/account IDs,
epoch, tick, native `Weight`/`MaxWeight`, count, one line per valid row and an
`end rows=` terminator. The closing message says the outcome is unverified.
The file contains no reference to the patched builtin (grep count 0).

**Patched-only** (`prontera,151,150`, `T10 Coin Capacity#t10cc`): GM gate,
confirmation, then before → call 1 → call 2 → after with no yield (the
`between` snapshot of the first candidate was removed in the budget
follow-up), plus a verbatim `r1`/`r2` result line. No grants or other mutation.

Every script variable written is `.@` scope (the follow-up also replaced `switch`, whose compiled form writes a `$@__SW…_VAL` temporary); `@inventorylist_*` are the native
temporary readouts. Readouts iterate only `.@i < @inventorylist_count`.
