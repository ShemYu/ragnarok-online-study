## Host behaviour

`node tools/renewal/probe_remaining_compiled_core.mjs --profile <p> --admission <a>`

1. **Arguments.** The CLI takes exactly the two flags with values. Missing,
   unknown, duplicate and `--flag=value` forms are refused. Node `execArgv` and
   `NODE_OPTIONS` are also refused. A refusal exits 2.
2. **Profile.** The profile is checked against the fixed 51941B/SHA pin, whatever
   its path. Then come the schema, `execution_admitted:false`, the exact
   eight-field identity order/encoding and all 12 frozen caps. The profile prefix
   and suffix descriptors must equal the hard pins.
3. **Separate admission.** The admission JSON's keys must be exactly `schema`,
   `root_bound`, `execution_admitted`, `mode`, `profile_sha256`, `output_path`
   and `host`. `host` must equal the running source's path/bytes/SHA and its
   eight decimal-string bigint identity. Any refusal happens before a body or
   source target is opened and before the output directory exists.
4. **Bindings.** The host requires 21 ordered maps and 55 distinct body paths;
   coinciding hashes are allowed. Each `rsw`/`gat`/`gnd` index must bind a body
   of that kind, and the RSW must be `data/<map>.rsw`. The Latin-1 embedded
   GAT/GND names must equal the bound terrain basenames. Every body must be used,
   with no RSW reused. Main bytes must be 103067388 and pilot bytes 4255734.
   Aliases are derived and recorded. On the real profile this gives exactly
   1@ch1b→1@ch1a, ch1_dw→1@ch1a, ch1_vrgef1→ch1_gef_in and ch1_vrgef2→ch1_geffen.
5. **Exact reads.** Each file is opened with `O_NOFOLLOW` and must have a canonical
   realpath and be a regular single-link file. The 8-field identity comes from
   bigint `fstat` as decimal strings and is never passed through `Number`. The host
   reads to EOF into a standalone `new ArrayBuffer(size)` (never pooled) and checks
   the full SHA. FD, path and parent identity must be stable around the read.
   Only the selected mode's bodies plus the prefix and suffix are read. The node
   binary (121911744B) is fully hashed against the profile; `process.execPath` must
   equal its path. Descriptors stay open until post-checks.
6. **Suffix.** Pilot mode passes the suffix through byte-for-byte unchanged. The
   host first renders the pilot's CH1_INPUTS and terrain assertion from the
   profile bindings. Each must occur exactly once in the unchanged suffix, which
   proves the template. The suffix must also contain `performance.now() + 48000`
   and `8 * 1024 * 1024`. For each remaining map, only those two regions are
   replaced. The record keeps the old/new text, the offsets, the 6828 preserved
   bytes and a complete inverse reconstruction that must equal the original.
7. **Worker.** Each map gets one fresh sequential `Worker`. It is this module in
   worker mode with `env:{}`, `execArgv:[]`, `maxOldGenerationSizeMb:1024` and
   captured stdout/stderr. The worker rehashes the payloads it receives and then
   installs explicit globals:
   - `self=globalThis`;
   - an `onmessage` accessor that records every assignment;
   - a `postMessage` → parentPort bridge;
   - `performance`, `crypto` (WebCrypto), `TextEncoder`/`TextDecoder`;
   - a fixed in-memory `fetch`.

   It then runs the prefix and suffix text as one classic script with
   `vm.runInThisContext`. That keeps the prefix's global `var`/`class` scope and
   the parser realm the same as the realm of the handed ArrayBuffers. Host
   bindings stay module-scoped, so the prefix's `var exports`/`var fs` cannot
   collide with them. `Headers`/`setImmediate` are captured before evaluation.
8. **Readiness.** The prefix's immediate `THREAD_READY` is only recorded. The parent
   sends `ROOT_CH1_CORE` only after a distinct `SUFFIX_INSTALLED` handshake. That
   handshake requires that evaluation completed, exactly one THREAD_READY was
   seen, and the last `onmessage` assignment came after it, with a different
   function. The worker then calls the *current* handler.
9. **Fetch adapter.** It serves only `/body/rsw|gat|gnd`, each once, with status 200
   and an exact `content-length`. It sends no transfer- or content-encoding.
   `arrayBuffer()` returns a fresh exact `slice(0)` and can be read only once.
   Unknown URLs reject. Every call, option set and handed buffer is recorded.
   There is no HTTP, browser, CDP, CLIENT_INIT, SET_HOST, LOAD_MAP, FileManager or
   texture/model/water acquisition.
10. **Lifecycle.** The host counts `ROOT_CH1_RESULT` messages and retains the first
    encoded string exactly. It then sends CLOSE. The worker rehashes every handed
    constructor buffer, reports its fetch ledger and any post-terminal messages,
    and closes its port. A *positive exit* means exit code 0, no terminate and a
    closing summary, with no worker error. A 55 s parent timer (bounded by the
    1240 s run timer) terminates only the owned Worker. The host sends no signals.
11. **Results.** Each started map gets four retained artifacts:
    - `<label>.core.json`: the exact encoded diagnostic string;
    - `<label>.suffix.js`: the exact projection (remaining21 only);
    - `<label>.host.json`: bindings, the projection record, lifecycle/bootstrap/
      handler/closing evidence, the script-message ledger, worker errors and
      streams.

    `MANIFEST.json` comes last. It lists every selected map in order as
    `not_started`/`failed`/`observed`; Root alone assigns `qualified`. It also
    records the pre/post-checks of every staged file, the profile, admission and
    host, plus stream use and aggregate bytes. The directory is 0700 and created
    exclusively. Files are 0600 with `O_EXCL|O_NOFOLLOW` and fsync. Caps are
    8MiB per file and 185597952B aggregate. The host makes no retries or deletions.
12. **Failure policy.** A host-lifecycle failure stops the batch fail-fast:
    timeout, bootstrap, duplicate terminal, non-positive exit, an adapter/buffer
    violation or core inputs that differ from the bound inputs. Every later map
    stays enumerated as `not_started` with a reason. A genuine diagnostic
    exception or incomplete observation is `failed`/`genuine`. It keeps its
    phase, name and message, and the batch continues. The suffix's
    `qualification:false` is recorded as policy metadata only. The exit code is 0
    only if every selected map is observed, all post-checks pass and the manifest
    is written. Otherwise it is 1.

## Limits and open risks

- No genuine prefix/suffix/body was evaluated, so real behaviour is unknown.
  Whether the prefix's top level runs cleanly in a Node worker, and whether the
  pilot equals the browser oracle (all hashes/rows except `elapsedMilliseconds`),
  is still Root's admitted checkpoint. Fake constructors prove plumbing only.
- Diagnostic `RSW.compile` runs before any texture load; production MapLoader
  order differs. That label is written into every report and the manifest. None
  of this is file-format validity, production LOAD_MAP, rendering, travel, story,
  save or 82-gap closure.
- The unchanged suffix's own behaviour is preserved, not altered. It slices
  `error.message`/`postcheckError` to 1200 characters, and it replaces an
  over-8MiB result with a bounded error. The host records whatever the suffix
  posts and does not recover a full message.
- The suffix's 48 s inner deadline is only checked between awaits and scan
  chunks. A synchronous constructor or compile block is bounded by the 55 s
  parent terminate, which then counts as a host failure.
- Worker heap limits do not cover ArrayBuffers. The 1610612736B RSS figure is
  Root's external sampling guard, not something this host contains. Root's
  external owned-Node guard is still required for actual execution.
- Policy choices Root may correct:
  - unknown admission keys are refused, which fails closed;
  - JSON duplicate keys inside the admission are not detected; `JSON.parse`
    keeps the last one;
  - canonical-path checks refuse symlinked parent components;
  - genuine exceptions continue the batch, while host failures stop it.
- The admission is a local Root-binding convention, not an adversarial sandbox.
