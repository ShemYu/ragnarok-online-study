## Cause (confirmed by host replay)

`lock_candidate` emitted rows in **name** order (`comm` output). The solver
delta (`parse_simulate`), `check_lock_file` and the host `_dep_lines` all use
complete `name=version` order. `-` (0x2d) sorts before `=` (0x3d), so the
orders differ for prefix pairs:

- **Actual delta:** `fmt-dev`/`fmt`, `git-init-template`/`git` and
  `libucontext-dev`/`libucontext`.
- **Actual 26-package base:** `alpine-baselayout-data`/`alpine-baselayout`
  and `busybox-binsh`/`busybox`.

The base freeze would therefore also have failed the build-mode
`check_lock_file` and the byte comparison against the qualified base. The
host's `_dep_lines` would likewise refuse that base as unsorted.

Base `a6103005` had a second, latent defect. `comm` sat in a pipeline whose
status came only from the `while` loop. A failing `comm` therefore produced
an empty result with success. In the production
`lock_candidate … > apk.base.current || die "base freeze"` context this froze
an **empty base** (reproduced by a test).

## Change

The candidate changes only these allowed files:

- `tools/renewal/native_capacity/build/guest_lib.sh`
- `tools/renewal/native_capacity/build/guest_build.sh`
- `tools/renewal/native_capacity/test_build_recipe.py`
- `tools/renewal/native_capacity/BUILD_RUNBOOK.md`
- this report

The `lock_candidate` changes in `guest_lib.sh` are:

- **comm status:** `comm -13` runs in a command substitution, with an explicit
  `|| die`.
- **No additions:** the function returns at once with zero bytes and success.
- **Loop in the current shell:** the per-name loop reads a here-document,
  not a pipe. Its `die` therefore ends the guest, even under
  `> f || die`, where `set -e` is suspended.
- **Lookup checks:** each lookup checks the `awk` status. The existing rule
  still refuses zero or several `name-<digit>` entries.
- **Canonical sort:** the rows are sorted with `LC_ALL=C sort`, without `-u`,
  inside a command substitution with its own `|| die`. No final pipe to
  `sort` can mask a refusal, and duplicates survive to the exact gates.

In `guest_build.sh`:

- `check_lock_file "$OUT/apk.base.current" nonempty` now runs immediately
  after the base freeze, so the base is canonical and unique in both modes.
- The resolve gate is unchanged. It is still an exact byte `cmp` of the
  candidate against the unchanged `apk-simulate.delta`, never a set or count
  test, and expected data was not edited.

`build_recipe.py`, production/native/story inputs, source preparation,
profiles and CI were not touched. The exact47 delta, base26, signatures,
offline install, raw Q1/C: identities, actual arch, native ARM64,
seven-field list, five-field manifest, fd0, resources and lifecycle code are
unchanged.
